# Как устроен Radmin VPN (разбор) и что из этого воспроизводит CSLVPN

Документ фиксирует **изучение предметной области**: что такое Radmin VPN, из
каких частей он состоит, какие решения в нём видны снаружи (по поведению,
сетевым артефактам и официальной документации) и какие из этих решений
перенесены в CSLVPN, а какие осознанно изменены.

> Источники: официальная документация Famatech (radmin-vpn.com, FAQ),
> обзоры и разборы 2025-2026 гг., наблюдения за поведением клиента
> (виртуальный адаптер, диапазон адресов `26.x.x.x`, режимы «direct/relay»).
> Radmin VPN — закрытый продукт, поэтому внутренний протокол ниже описан как
> **модель**, а не как результат реверс-инжиниринга.

---

## 1. Что это такое

Radmin VPN — **не** privacy-VPN. Он не прячет ваш публичный IP и не гоняет
весь трафик через зарубежные серверы. Его задача — построить **виртуальную
локальную сеть (VLAN, L2/L3 overlay)** между компьютерами, находящимися за
NAT, так, чтобы игры, SMB-шары, RDP и легаси-софт «видели» друг друга как в
одном офисе.

Ключевые свойства, которые видит пользователь:

| Свойство | Как проявляется |
|---|---|
| Создание сети | «Create network»: имя сети + пароль, без регистрации и аккаунтов |
| Вход в сеть | «Join network»: те же имя + пароль с другой машины |
| Виртуальный адрес | автоматический, в диапазоне `26.x.x.x` |
| Изоляция | члены разных сетей не видят друг друга, хотя у них могут быть одинаковые имена |
| Изоляция от интернета | в туннель попадает только трафик к виртуальным адресам |
| NAT traversal | работает за домашними роутерами и CGNAT, без проброса портов |
| P2P или релей | сначала пробуют прямой канал, иначе — через сервер-ретранслятор (в UI видно «Relayed» и более высокий пинг) |
| Шифрование | AES-256 внутри виртуальной сети |
| Лимиты | ~150 устройств на сеть, ~100 Мбит/с |
| Платформы | только Windows (NDIS/TAP-драйвер + служба) |

## 2. Архитектура (модель)

```
        ┌────────────────────── координационный сервер (Famatech) ─────────────────────┐
        │  реестр сетей (имя → соль), выдача виртуальных адресов, обмен endpoint'ами,    │
        │  релей-серверы для пар, которым не удался прямой канал                        │
        └───────────────▲───────────────────────────────────────▲──────────────────────┘
                        │ сигнализация (TCP/TLS)                │
        ┌───────────────┴───────────┐                 ┌─────────┴─────────────────┐
        │ клиент A                  │◄─── P2P UDP ───►│ клиент B                  │
        │ виртуальный адаптер       │  (если NAT       │ виртуальный адаптер       │
        │ 26.x.x.x, шифрование      │   позволяет)     │ 26.y.y.y, шифрование      │
        └───────────────────────────┘                 └───────────────────────────┘
```

Слои:

1. **Драйвер виртуального адаптера.** NDIS-фильтр / TAP-подобное устройство.
   В Windows создаёт сетевое подключение, которое приложения видят как обычный
   Ethernet. В Linux эквивалент — `TUN` (`/dev/net/tun`), именно его использует
   CSLVPN.
2. **Служба/демон.** Поднимает адаптер, настраивает адрес и маршруты, держит
   туннели, шифрует кадры.
3. **Сигнализация.** Регистрация в сети по имени+паролю, получение
   виртуального адреса, обмен «кто в сети» (список пиров), попытка P2P.
4. **Транспорт данных.** Шифрованные кадры между участниками; при
   невозможности прямого соединения — через ретранслятор.
5. **Ретранслятор.** Пересылает кадры между участниками одной сети, не давая
   трафику выйти за её пределы.

### 2.1. Адресация

Виртуальные адреса выдаёт координационный сервер (в CSLVPN — ретранслятор).
Диапазон `26.0.0.0/8` выбран так, чтобы почти гарантированно не пересекаться с
домашними/корпоративными подсетями (`192.168.*`, `10.*`, `172.16-31.*`) и не
ломать маршрутизацию. В CSLVPN каждая сеть получает свой `/24` внутри
`26.0.0.0/8` (например `26.0.0.0/24`, `26.0.1.0/24`, …), клиенты — адреса
`.2`…`.254`.

### 2.2. Почему нужен ретранслятор

Прямой UDP-канал между двумя клиентами за симметричным NAT/CGNAT часто
невозможен: NAT не пропускает «чужие» входящие пакеты без предварительного
исходящего в тот же адрес:порт. Тогда остаётся единственный путь — оба клиента
имеют **исходящее** соединение с узлом, у которого есть «белый» IP, и он
пересылает кадры между ними. Это и есть модель, которую реализует CSLVPN:
сервер с белым IP = точка встречи + ретранслятор + шлюз в интернет.

### 2.3. Шифрование

Radmin VPN заявляет AES-256 на уровне туннеля. CSLVPN использует AES-256-GCM
на каждый кадр (аутентифицированное шифрование), эфемерный X25519 для
согласования ключей (forward secrecy) и PBKDF2-SHA256 для пароля сети.
Подробности — в [PROTOCOL.md](PROTOCOL.md).

## 3. Что Radmin VPN делает хорошо и какие у него ограничения

**Сильные стороны:** нулевая настройка (сеть по имени+паролю), работа за
любым NAT, изоляция сетей, «как в локальной сети» для любых приложений.

**Ограничения:**

* только Windows — нет клиентов для Linux/macOS/Android;
* закрытый код и закрытый протокол: нельзя развернуть собственный сервер и
  нельзя проверить, что происходит внутри;
* нет выбора транспорта: если UDP в сети запрещён (корпоративный фаервол,
  некоторые мобильные/гостевые сети), подключения нет;
* трафик между участниками может идти через третью сторону (серверы
  производителя);
* нет управления: нельзя выделить адрес вручную, нельзя посмотреть, кто в сети
  с сервера, нельзя кикнуть участника.

## 4. Что реализует CSLVPN

| Возможность Radmin VPN | Реализация в CSLVPN | Где |
|---|---|---|
| Создать сеть по имени и паролю | `cslvpn client -create -network office -password ...`; сеть создаётся на первом входе | `internal/relay/network.go` |
| Войти в существующую сеть | те же параметры без `-create` | `internal/client/client.go` |
| Автоматический виртуальный адрес `26.x.x.x` | выдача свободного адреса в `/24` сети; можно попросить конкретный (`-ip`) | `internal/relay/network.go` |
| Список участников сети | `FRAME_PEER_LIST` при каждом изменении состава, лог в клиенте (`-v`) | `internal/relay/server.go` |
| Изоляция сетей | сервер пересылает только внутри `/24` своей сети; чужие адреса отбрасываются | `internal/relay/server.go` (`forward`) |
| Шифрование AES-256 | AES-256-GCM на кадр, X25519 + PBKDF2 для ключей | `internal/crypto` |
| Работа за NAT без проброса портов | оба конца инициируют исходящее соединение к ретранслятору | `internal/client/link.go` |
| Ретранслятор на белом IP | `cslvpn server -listen :7777` | `cmd/cslvpn/server.go` |
| Ручное управление | админ-API: список сетей/участников, kick с баном, статистика | `internal/relay/admin.go` |
| Лимиты (участники, сети) | `-max-members` (по умолчанию 150), `-max-networks` | `cmd/cslvpn/server.go` |

### 4.1. Главное отличие: выбор UDP или TCP

Radmin VPN использует свой транспорт и не даёт выбора. В CSLVPN транспорт —
**явный параметр клиента** (`-transport udp` или `-transport tcp`), который
проверяется на сервере:

* сервер слушает **один и тот же порт** и по UDP, и по TCP;
* клиент указывает выбранный транспорт в первом же пакете (`Hello`), сервер
  сверяет его с тем сокетом, через который пришёл пакет, и отказывает при
  несовпадении (код `ERR_BAD_REQUEST`);
* транспорт подтверждается в кадре `Welcome` и виден в списке пиров;
* разные участники **одной сети могут использовать разные транспорты** —
  кадры между UDP-клиентом и TCP-клиентом ретранслируются без потерь
  (см. `scripts/e2e-test.sh`, где alice — UDP, bob — TCP).

Практический смысл: в сетях, где UDP режется, работает `-transport tcp`; где
нужна минимальная задержка и допустимы потери — `-transport udp`.

### 4.2. Что добавлено сверх Radmin VPN

* **Интернет через сервер** (`cslvpn client -internet` + `cslvpn server
  -gateway`): клиент получает default route в туннель, сервер выполняет NAT.
  Это классический VPN-шлюз, которого у Radmin VPN нет; изоляция сетей при
  этом сохраняется (см. `scripts/nat-test.sh`).
* **Кроссплатформенность**: один Go-бинарник на Windows/Linux/macOS, без
  драйверов ядра (TUN через `/dev/net/tun` в Linux; Windows — см.
  [WINDOWS.md](WINDOWS.md)).
* **Открытый протокол** с тестами и эталонной реализацией
  ([PROTOCOL.md](PROTOCOL.md)).

### 4.3. Чего пока нет (осознанно вне рамок)

* **Прямой P2P-канал (UDP hole punching)** — сейчас весь трафик идёт через
  ретранслятор. Это проще, предсказуемее и всегда работает за NAT; при
  необходимости P2P добавляется как «оптимизация поверх» (см.
  [ROADMAP.md](ROADMAP.md)).
* **L2-широковещание** (ARP, NetBIOS, обнаружение игр в локальной сети) —
  CSLVPN работает на L3 (IP). Broadcast-зависимые игры требуют эмуляции
  широковещания, это следующий шаг дорожной карты.
* **Полноценный GUI** — сейчас CLI (+ план в ROADMAP).

## 5. Итоговая схема CSLVPN

```
                    сервер с белым IP (ретранслятор + шлюз)
                   ┌─────────────────────────────────────────┐
   клиент A        │  UDP :7777 ─┐                           │
   (26.0.0.2) ─────┼────────────►│  реестр сетей             │
   udp или tcp     │  TCP :7777 ─┤  ├─ сеть "office" /24      │──── NAT ──► интернет
                   │             │  │   ├─ A 26.0.0.2 (udp)   │   (опционально, -gateway)
   клиент B        │             │  │   ├─ B 26.0.0.3 (tcp)   │
   (26.0.0.3) ◄────┼─────────────┘  │   └─ C 26.0.0.4 (udp)   │
   tcp             │                └─ сеть "home" /24 (изолирована)
                   │  админ-API 127.0.0.1:7778 (статистика, kick)
                   └─────────────────────────────────────────┘
```

* кадры шифруются на каждом конце (сквозное шифрование, сервер видит только
  заголовок IP, чтобы знать адресата);
* сервер никогда не отдаёт трафик из одной сети в другую;
* участники одной сети могут использовать разные транспорты.
